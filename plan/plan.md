Two final fixes before 1.1.0
1. Operations snapshot diff still runs synchronously. In pages/operations.py, _render_diff() directly calls OperationsAnalytics.snapshot_diff(...) from the UI callback and also runs once when the drawer opens. Convert that to the same run.io_bound() + loading-state pattern already used elsewhere. It is probably a small query, but leaving one exception breaks the clean runtime invariant we worked hard to establish.
2. The large retained-payload UI still takes the old full-bytes path. The excellent new OperationsAnalytics.export_source_payload_to_file() incremental blobopen() implementation exists and is tested, but the actual Operations download handler still calls source_payload(), materializes the whole BLOB, and only afterward writes large payloads to a temp file. Change the UI branch to use the already-built streaming method whenever byte_len > _INLINE_PAYLOAD_THRESHOLD_BYTES; keep source_payload() only for small inline downloads.
